# 최초 GitHub 공개 업로드

대상은 **`MongLong0214/tetra-atlas`**입니다. 실제 생성 완료를 의미하지 않습니다.

## Work 실행 결과 — 2026-10-04

연결 계정은 `MongLong0214`로 확인했습니다. 대상 저장소 조회는 `404 Not Found`, 계정 내 저장소 검색은 빈 결과입니다. 저장소 부재인지 연결의 접근 권한 부족인지는 구분하지 못했습니다. 이번 Work에서는 원격 쓰기를 시도하지 않았습니다.

현재 연결에는 파일·커밋 쓰기 기능이 있으나 저장소 생성 기능은 없습니다. 새 환경에도 GitHub CLI와 GitHub 토큰이 없어 최초 게시 스크립트를 실행하지 않았습니다. 원격 파일·HEAD·공개 범위·Actions·배포는 미확인입니다. 다른 계정이나 저장소는 변경하지 않았습니다.

브라우저로 전환하려면 현재 브라우저 도구 지침상 사용자 확인이 필요합니다. 확인 후 계정과 대상 저장소의 존재·공개 범위부터 읽고, 기존 저장소가 있다면 HEAD·파일을 비교해 이력을 보존해야 합니다. 개인 토큰을 채팅에 제공할 필요는 없습니다.

로컬에서는 Node 24의 57개 검사, 실제 HTTP Chromium의 기존 29개와 추가 16개 검사, GLES 8개 검사가 통과했습니다. 정확한 범위는 [검증 기록](VALIDATION.md)을 참조하세요. 이 결과는 원격 게시나 정식 프로덕션 승인을 뜻하지 않습니다.

## 별도 로컬 환경의 최초 게시 도우미

Node.js **22 또는 24**, npm, Git, [GitHub CLI](https://cli.github.com/)가 필요합니다. 인증이 없으면 CLI 브라우저 로그인을 사용합니다.

```bash
cd tetra-atlas
bash scripts/publish-github.sh
```

소유자 확인 → 동명 저장소/.git 존재 시 중단 → 테스트/빌드 → 명시적 파일 목록의 최초 커밋 → 새 공개 저장소 생성/푸시 → 원격 공개 상태와 SHA 일치 확인 순서입니다. 개인 이메일 대신 GitHub noreply 주소를 사용합니다. 실패하면 자동 강제 재시도하지 않습니다.

이미 공개 저장소를 만든 경우 이 도우미는 안전을 위해 중단합니다. 기존 내용을 덮어쓰는 도구가 아닙니다. 리뷰 증거는 `docs/review/`에 포함되며 일시적인 `tests/review-output`, `dist`, `.env*`, 개인 키, `.vercel`, `node_modules`, `.venv`는 제외합니다.

전역 Git 설정, GitHub Pages, Vercel 도메인/프로젝트, 라이선스는 변경하지 않습니다. 이 환경에서 확인한 것은 구문과 로컬 테스트뿐이며 인증·생성·푸시 end-to-end 검증이 아닙니다.

참고: [gh repo create](https://cli.github.com/manual/gh_repo_create).
